# Crosshair designer

Open **Settings → Gameplay Overlay → Custom Crosshair**. The section contains 16 named presets, a vector designer, and a custom PNG tab. All settings save automatically through the existing settings pipeline; the HUD enabled switch is independent of the preview.

**Library** is the first and initially selected tab. The header switch uses the same dimensions, border, and spacing as neighboring overlay controls; its crosshair icon matches the muted orange of neighboring active overlays. For any active image crosshair, a shared **Crosshair size** slider below the live preview adjusts the actual HUD size from 1 to 256 CSS pixels. It preserves the original animated bytes and works directly from the library as well as the custom-image tab. Preview zoom remains independent of the HUD size.

Position uses four directional buttons and **Center**, with one pixel per click or ten with Shift. Its status describes the offset in words instead of requiring X/Y input. The enabled icon uses the same muted orange (`#d3a783`) and background as neighboring active overlay icons, without an additional glow/filter.

Size, position, rotation, opacity, and designer appearance are stored per crosshair in `crosshairProfiles`, without copying image/animation data. Library items use their stable page identifier, presets retain an identity while edited, and local images use a content fingerprint rather than a potentially ambiguous filename. Selection and profile snapshots are committed in the same settings transaction; a previously used crosshair restores its own values and new designs start centered. The existing active crosshair is migrated by capturing its current values on the first edit or selection change. Profile history is bounded to 256 designs, with the most recently edited/selected retained.

Each library card has a separate star button. Favorites are available in a dedicated **Favorites** view with search and are saved automatically through the standard settings persistence path. Only validated provider-owned page/image links and names are stored, with a maximum of 200 entries; image/animation bytes are not duplicated. Favorites remain available across category changes and app sessions. Removing a favorite does not disable or change the currently active crosshair.

The **Library** tab browses CenterPoint Gaming's public Crosshair X gallery. Style, game, color, and collection categories are read from the provider; results load one page at a time, with search explicitly scoped to that page. Only eight HTML responses are cached in memory for ten minutes. Opening other settings does not load the library code or contact the provider.

Selecting a design reads its detail page and downloads the original transparent WebP through the secured main-process bridge. Animated WebP is preserved byte-for-byte rather than flattened to PNG. Large static originals are resized to a transparent PNG at most 256 pixels wide/high, with a smaller retry if necessary. Source downloads are capped at 2 MiB and static canvases at 2048 pixels; animations allow up to 768 KiB, 1024-pixel canvases, 1500 frames, and 16 million pixels across actual frame rectangles. Sparse animation updates are counted by their real area rather than incorrectly charging every update as a full canvas. Only provider-owned HTTPS asset addresses are accepted and redirects are rejected. Unsupported, missing, or excessive images leave the previous crosshair unchanged and return a structured error instead of an unhandled IPC rejection. The selected image and its source attribution are saved locally, so the HUD does not need an ongoing connection to the gallery. Local PNG import remains available independently.

Category selection uses a grouped, keyboard-accessible listbox in a portal, avoiding clipping by the settings accordion. It closes on Escape, selection, or outside click, restores focus appropriately, positions itself above/below the trigger according to available space, and supports reduced motion. Opening animates only opacity and a small vertical translation, with no horizontal movement or text scaling. Static WebP resizing uses Chromium's asynchronous bitmap decoder, since Electron nativeImage cannot decode the tested WebP files on Windows. Animations also have a 32-million-pixel upper bound for worst-case composited-frame caching.

This integration uses the current public website markup, not a documented API; provider changes or restrictions may interrupt browsing. It does not duplicate the entire gallery or download Steam Workshop packages. Designs remain attributed to their source; a public/commercial distribution must have appropriate provider/content permissions.

The vector renderer supports cross, diagonal cross, ring, box, diamond, and chevron shapes, with line length/width, gap, center dot, outline, rounded ends, T-shape, rotation, opacity, color, and center offsets. Preview and native HUD use the same normalized configuration and SVG component. At 1× the preview uses the same CSS-pixel size; 0.5× and 2× are preview-only zoom levels. Scene, dark, and light backgrounds are local static CSS and do not run animation loops.

PNG imports accept at most 2 MiB and 1024 × 1024 pixels. Headers are checked before decoding. Decoded images are re-encoded to bounded static PNGs of at most 256 × 256 pixels, with transparency preserved; fully transparent and invalid files are rejected. The compact raster is stored locally in settings, so the original file is not needed after import. Imported image colors are preserved. Removing the image returns to the saved vector design. Neither import nor rendering accesses game processes or modifies game files.

The clip notification now starts thumbnail capture directly from the already-active recording stream and updates the pending toast in place. Preview updates cannot reopen dismissed notifications or change a completed clip back to “saving.” If the capture source does not provide a readable frame, the notification retains its fallback icon.

Tests cover configuration bounds, symmetric X geometry, image-header limits, unsafe image sources, real PNG import, saved settings, identical preview/native SVG, narrow layouts, language switching, mode changes, and pending-thumbnail notification behavior.
